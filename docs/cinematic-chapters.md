# Cinematic chapters / 映像的な記事制作ルール

このサイトの記事本文は `public/data/thought-nodes.json` が唯一の原本。本文の追加・修正は作者が提供・承認した文章のみ。演出のために文章を書き換えたり、要約して本文扱いしたりしない。

## 実装構成

- `public/collage.js` は原稿の読み込みと基本の誌面を担当する。章の描画が終わると `thought:render` イベントを送る。
- `public/cinema.js` は章ごとのストーリーボード、本文に由来するレタリング、Canvas 2D の場面別モーションを担当する。本文 DOM を書き換えず、対応する段落の**後ろ**に映像シーンを挿入する。
- `public/cinema.css` はタイプデザイン・色・動き・レスポンシブ・章切替演出を担当する。
- 既存の `motion.js` / `motion.css` は通常の文章の登場と初期の操作ギミックとして残す。

## 新しい記事を実装するとき

1. 原稿の段落数と、それぞれの主題を確認する。本文の配列は変更しない。
2. `cinema.js` の `SCENES` に記事IDを追加する。各段落に `[巨大レタリング, 文章からの正確な抜粋, motion mode, 背景の漢字, 英文のフィルムラベル]` を一件ずつ指定する。
3. レタリングの主題と場面の運動は、**文章の意味と対応**させる。雹なら落下、朧気なら流動、400年なら減衰、神なら凝集など、単なるフェードインの使い回しにしない。
4. 新しい場面には `cinema.css` で独自の美術設計を与え、必要なら `cinema.js` の描画処理を追加する。
5. 原文からの抜粋は `.copy.textContent.includes(excerpt)` で照合される。不一致の場合、その章の映像演出を安全のため生成しない。
6. モバイルとデスクトップの両方で文字の折り返し、スクロール、インタラクションを確認する。視覚的なグラフィックスが本文を覆ってはならない。
7. `prefers-reduced-motion` と「演出を止める」ボタンに対応する。点滅するストロボ演出や自動音声は使用しない。
8. `thought.html` と `collage.html` のキャッシュバージョンを更新して、公開後に古い CSS / JS が残らないようにする。

## 負荷と操作

表示されている場面だけを `IntersectionObserver` で検出し、Canvas を最大約30fps（低性能端末は24fps）で更新する。ピクセル密度は上限1.6、狭い画面では1.25。非表示タブでは停止。通信量節約設定や動きを減らす設定では静止画にする。ボタンはスマートフォンのタッチとキーボードに対応。

## 完成判定

JavaScript の構文検証、CSS の括弧検証、全段落と全場面の照合、既存の前後ナビゲーションと原文不変の確認を通す。実機での視覚確認と公開先の反映確認は別工程として明記する。
