# すべての歯が見える 制作ルール集

最終更新: 2026-08-22
用途: 切り抜き動画・VRM動画・アーカイブ化作業の恒久ルール。

## 0. この文書の役割

この文書は、配信アーカイブの処理・切り抜き動画化・VRM動画化を行う際の恒久ルールである。

## 1. 最重要原則

### 1-1. 嘘の同期をしない
- 字幕タイミングを勘で置かない。
- 要点テロップを字幕の代わりに使う場合は「字幕」ではなく演出テロップとして扱う。
- 単語や文の同期が必要な動画では、Whisper等の実タイムコードを基準にする。
- 前後のズレを手動補正する場合も、補正理由を残す。

### 1-2. 実音声を必ず使う
- 話者本人の配信切り抜きは必ず元配信の実音声を使う。
- 別音声、仮音声、代替読み上げ、無音での仮動画を完成品扱いしない。

### 1-3. 未完成物を完成品扱いしない
- 草案、動作確認、モック、検証用はそのように明記する。
- 「できた」と言うのは目的達成条件を満たした時だけ。

### 1-4. 指摘は防御せず検証する
- 字幕がズレている
- 口が動いていない
- 客の声で口が動いている
- Tポーズである
- 内容が違う
- GitHubに入っていない

上記の指摘が出た場合は、まず再現・検証する。

## 2. アーカイブ化ルール

配信1本ごとに最低でも以下を残す。

1. original: 原文そのもの
2. semantic-translation: 意味が通るように整えた版
3. meaning-extraction: 語られていた内容の抽出
4. knowledge: 再利用しやすい知識・思想・設定
5. video-ideas: 動画化候補

original は改変しない。文脈で確定できるASR誤認識は semantic-translation 以降で直す。

相談者の個人情報、病歴、住所推定、アカウント特定情報は公開素材から外す。公開切り抜きでは配信者本人の独話部分を優先する。

## 3. 動画化ルール

動画候補の優先順位:
1. 独話で成立する
2. オチがある
3. 短く切れる
4. 個人情報リスクが低い
5. キャラクター性が出る

尺の目安:
- 第一候補: 20〜45秒
- 第二候補: 45〜75秒
- 原則90秒以内

タイトルは説明ではなく異常事態を一言で表す。

## 4. 字幕ルール

### 4-1. 逐語字幕
- Whisper等の実タイムコードを使う。
- 聞こえる順序に合わせる。
- ASR由来の人工ギャップを補正する場合は理由を残す。

### 4-2. 演出テロップ
- 要約文は逐語字幕と混同しない。
- フック・見出し・意味整理用として扱う。

### 4-3. 同一音声ソース

字幕、話者分離、口パクエンベロープは、**同じ切り出し済み PCM WAV** を正本とする。

```text
元音声
  → atrim
  → asetpts=PTS-STARTPTS
  → voice.wav
      ├─ timed ASR
      ├─ speaker diarization
      └─ lip-sync envelope
```

別々の中間音声を使わない。

## 5. VRM動画ルール

### 5-1. 動画用モデル

動画用は `Subeha.vrm` を正本とする。

`subeha-web-site.vrm` はWeb表示用の軽量モデルであり、動画口パクには使用しない。

動画レンダー前に口表情 `aa / ih / ou / ee / oh` の存在を検査し、不足していれば停止する。

### 5-2. 完成条件

- Tポーズでない
- 腕・姿勢が自然
- 本人の実発話中に口が動く
- 客・相談者・ゲストの発話中は口が閉じる
- 字幕またはテロップが意図通り
- 冒頭・中盤・オチを検品済み

### 5-3. 話者ゲート

アバターは配信者本人を表す。

**音量だけで口パクを駆動して本番完成品にしてはいけない。**

話者分離結果を `HOST / GUEST` 等の区間に変換し、HOST区間だけ口パクエンベロープを通す。話者区間が無い場合、本番レンダーは失敗させる。

話者区間は対象音声の SHA-256 と音声長へ結び付け、別音声の区間データを誤適用しない。

### 5-4. モーション

- 基本姿勢は自然体
- 軽い呼吸、瞬き、頭部・上半身の微動は可
- 意図しないTポーズは禁止

## 6. Web制作アプリの役割

日常の制作入口は `tools/vrm-talker/` とする。

目標:

```text
音声を入れる
→ 字幕生成
→ 話者分離
→ VRMが本人発話だけで動く
→ 参考画像を検索 / 生成
→ レイアウト
→ プレビュー / 録画
```

Webアプリは素早い編集・確認・素材選択を担当する。

## 7. Remotionの役割

`remotion/vrm-lipsync/` は高品質な決定論的レンダー、再現可能なバッチ処理、最終QC用とする。

WebアプリとRemotionで別々の音声区間・字幕・話者データを作らない。共通の project/job JSON を受け渡す構成へ寄せる。

## 8. QC

機械QC:
- 動画ストリームが途中終了していない
- 期待する縦横比
- 音声ストリームあり
- A/V尺差が許容範囲
- VRMに必要な口表情あり
- 話者ゲートあり

目視QC:
- 本人発話で口が動く
- 客発話で口が閉じる
- 姿勢が自然
- 字幕同期
- 画面外クリップなし
- SNS UIに字幕が隠れない

## 9. GitHub保存ルール

「GitHubに入れた」と言ってよいのは、書き込み後に実際にfetch/readして存在確認した時だけ。
