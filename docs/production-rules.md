## 0. この文書の役割

この文書は、配信アーカイブの処理・切り抜き動画化・VRM動画化を行う際の**恒久ルール**である。
今後のチャットでは、この文書を参照して作業を進める。毎回同じ注意事項を言い直させないためのもの。

---

## 1. 最重要原則

### 1-1. 嘘の同期をしない
- 字幕タイミングを勘で置かない。
- 要点テロップを字幕の代わりに使う場合は、**「字幕」ではなく演出テロップ**として扱う。
- 単語や文の同期が必要な動画では、**Whisper等の実タイムコードを基準**にする。
- 前後のズレを手動補正する場合も、補正理由を明示する。

### 1-2. 実音声を必ず使う
- 話者本人の配信切り抜きは、**必ず元配信の実音声**を使う。
- 別音声、仮音声、代替読み上げ、無音での仮動画を完成品扱いしない。

### 1-3. 未完成物を完成品扱いしない
- 草案、動作確認、モック、検証用はそのように明記する。
- 「できた」と言うのは、少なくとも目的達成条件を満たした時だけ。
- 誤魔化しで出した動画は納品しない。

### 1-4. ユーザーの指摘が正しければ即認める
- 字幕がズレている。
- 口が動いていない。
- Tポーズである。
- 内容が違う。
- GitHubに入っていない。

上記は、ユーザーがそう言った時点でまず疑い、**防御ではなく検証**する。

## 2. アーカイブ化ルール

### 2-1. 保存すべきファイル
配信1本ごとに最低でも以下を残す。

1. **original**: 原文そのもの（ASRの誤字も含めて保存）
2. **semantic-translation**: 意味が通るように整えた版
3. **meaning-extraction**: 何が語られていたかの抽出
4. **knowledge**: 再利用しやすい知識・思想・設定の抽出
5. **video-ideas**: 動画化候補の抽出

### 2-2. original の扱い
- 原本は**改変しない**。
- 明白な誤認識があっても、original では原則そのまま保存する。
- 例: 「家」と認識されても、original ではそのまま残す。

### 2-3. semantic-translation の扱い
- 文脈で確定できる誤認識は直す。
- 例: 「家」→「遺影」
- ただし、意味が確定できない部分を勝手に創作しない。

### 2-4. 相談内容の扱い
- 相談者の個人情報、病歴、関係性、住所推定、アカウント特定情報は公開向き素材から外す。
- 公開切り抜きでは、**配信者本人の独話部分を優先**する。

## 3. 動画化ルール（共通）

### 3-1. 動画候補の選び方
優先順位は以下。

1. **独話で成立する**
2. **オチがある**
3. **短く切れる**
4. **個人情報リスクが低い**
5. **キャラクター性が出る**

### 3-2. 尺の基準
- 第一候補: 20〜45秒
- 第二候補: 45〜75秒
- 長くても 90秒前後
- 2分を超える場合は、原則として別動画に分割する

### 3-3. タイトルの考え方
- 説明ではなく**異常事態を一言で言う**。
- 例:
  - 遺影をAIでカード化したら破門された
  - 神様は毎年ドラフトした方がいい
  - 幽霊にも表示バグがある
  - うんこマンで教師を辞めた

### 3-4. 仕上げ前の確認項目
- 音声は元配信か
- 字幕は音声に合っているか
- 動画尺は長すぎないか
- オチまで含まれているか
- 個人情報を漏らしていないか
- サムネ・フックが立っているか

## 4. 字幕ルール

### 4-1. 逐語字幕
- 逐語字幕をつけるなら、Whisperやタイムコード付き認識を使う。
- 字幕は**聞こえる順序**に合わせる。
- 不自然な0.5秒ギャップなど、ASR由来の人工間隔がある場合は補正可。

### 4-2. 演出テロップ
- 逐語ではなく要約テロップを出す場合は、それを字幕扱いしない。
- 要約テロップは、話の要点整理・フック強化のために使う。
- 「音声通りに読ませる字幕」と「意味カード」は混同しない。

### 4-3. テロップの優先度
優先順:
1. 聞き取れないと意味が崩れる箇所
2. オチ
3. 固有名詞
4. 長い理屈の見出し化

## 5. VRM動画ルール

### 5-1. 完成条件
VRM動画を完成品と呼んでよいのは、以下を満たした時のみ。

- **Tポーズでない**
- **腕・姿勢が自然**
- **口が実音声に反応して動く**
- **字幕またはテロップが意図通り**
- **少なくとも3箇所（冒頭・中盤・オチ）を検品済み**

### 5-2. 禁止事項
- 動かないVRM静止画を完成品扱いしない
- 口の動かない既成MP4をループしてごまかさない
- 実同期がないのに「字幕版」と言わない

### 5-3. 口パク
- 音声エンベロープまたは口パク用データで制御する。
- 口が開閉しているだけでなく、**喋っている箇所で反応していること**を確認する。

### 5-4. モーション
- 基本姿勢は自然体。
- 軽い呼吸、瞬き、頭部の揺れは可。
- 演出で意図しない限り、十字架/Tポーズは禁止。

### 5-5. 仕上げ前の検品
最低でも次を確認する。
- 00:03 前後
- 中盤の喋りが強い箇所
- オチの箇所

確認内容:
- 口が動くか
- 腕が自然か
- 字幕が合っているか
- 音切れがないか

## 7. GitHub保存ルール

### 7-1. 「入れた」の定義
「GitHubに入れた」と言ってよいのは、
- ファイル作成後、
- 実際に fetch / read して、
- 内容が存在確認できた時のみ。

### 7-2. 索引だけで完了扱いしない
- index / archive だけを作って「全部保存した」と言わない。
- 全文、翻訳、抽出、知識、動画候補まで必要なら全部入れる。

## 9. 今回の反省をルール化した要約

- できていないものを、できたと言わない。
- VRMは実際に動いてから出す。
- 字幕は勘で置かない。
- GitHubは読んで確認してから「入った」と言う。
- ユーザーの指摘を最優先で検証する。
