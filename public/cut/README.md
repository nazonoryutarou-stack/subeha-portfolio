# SUBEHA CUT Pro v0.8 — video-frame masking and motion retouch

Android Chrome向けの、素材を端末内で処理する独立開発の動画編集PWA。
Videoleap/Lightricksとは無関係。専用UIのコード・ロゴ・有料テンプレートは複製しない。

## v0.8でできるようになったこと

- **動画の背景色切り抜き（動画マット）**：背景の色をスポイトで選び、フレームの外周とつながる似た色の領域のみを透明化。従来の色全体に対するクロマキーよりも、被写体の内側の同色領域を残しやすい。ただし半透明の髪や複雑な遮蔽は苦手。
- **動画の部分修復（クローン）**：修復したい点と周辺のコピー元をタップし、毎フレーム同じ範囲から画素をコピーする。不要物の周囲に適した背景がある映像向け。**AI生成による消去ではない。**
- **位置キーフレーム**：クローン修復の対象位置をクリップの再生時刻に沿って補間。追跡を自動推論するのではなく手動でキーを登録する方式。
- **ベースクリップ・動画オーバーレイ両対応**：ベース動画の背景消去、別動画に重ねた前面動画の切り抜きを両方サポート。生成したマットは従来のブレンド・マスク等との併用が可能。
- **非破壊編集とアーカイブ**：修復設定はクリップ/レイヤーのJSONデータに保存。元動画は変更しない。既存の素材入り`.subecut`バックアップにも設定が保存される。過去のv0.1–v0.7プロジェクトも従来通り読み込める。
- **書き出し時も適用**：再生プレビューとMediaRecorderの書き出しは同じCanvas2D描画関数を経由する。書き出し中に独立したAI処理を走らせるわけではない。

## 使い方

1. `https://nazonoryutarou-stack.github.io/subeha-portfolio/cut/` をAndroid Chromeで開く。アプリとしてホーム画面に追加できる。
2. 動画を読み込む。別の動画に人物等を重ねたい場合は「オーバーレイ」から前面の動画を追加する。
3. 下部ツールバーを横にスクロールして「**動画修復**」を開き、「**加工対象**」でベースまたは前面レイヤーを選ぶ。
4. 「背景を抜く」ではプレビュー上の背景色をタップし、色の許容差・境界ぼかしを調整。背景色が均一でない場合は上手く抜けない。
5. 「部分修復」では消したい点→コピー元の順でタップ。動く対象には再生時刻を変更し「◆この位置を修復の追従キーに保存」を複数地点で使う。
6. 必要に応じて開始・終了時刻と処理解像度（360/512/720）を調整。「出力」から動画を保存する。

## 検証と検出した不具合

```bash
cd public/cut
for f in *.mjs; do node --check "$f" || exit 1; done
node --test test/*.test.mjs
```

- **16系統の自動テスト成功**（既存15系統＋動画修復の画素処理・時系列テスト）。
- ローカルのChromium（幅390px）へソースを直接読み込ませ、**動画MP4を2本取り込み→前面レイヤー選択→緑背景除去→動画書き出し**まで実行。最初は前面レイヤーの選択肢が正しく表示されない不具合を検出し修正した。
- 検証用動画は約2.06秒、720×1280、MP4コンテナを生成できた。今回の検証環境では**VP9映像＋Opus音声のMP4**だった。一般的なH.264/AACのMP4とは異なるため、全端末・SNSでの再生互換性は保証できない。
- Chromiumの通常のローカルページ遷移は管理ポリシーで拒否されたため、テストはモジュールをインラインで読み込む方式で実施した。
- **Nothing Phoneの実機テストは未実施**。特に長尺、720px処理、大量レイヤー、端末熱・保存容量は未検証。

## 限界

**動画に対するセマンティック人物切り抜き、生成AIによるインペインティング、機械学習による自動モーションマスクではない。** 背景消去は色と外周連結、修復は近傍の画素コピー。複雑な背景、動くカメラ、大きい不要物、髪の毛には弱い。端末のCPUで毎フレーム処理するため、HD/4K素材や多レイヤーではフレーム落ちの可能性がある。加工は最大720px辺の一時バッファ経由となり、最終解像度へ拡大されるため細部が低下する場合がある。

ほかにも、4K/HEVC保証、全形式のMP4出力、ネイティブAPK、GPUオフラインレンダラー、Videoleapの全AI機能・テンプレート・有料素材は未実装。既存の字幕、音声EQ、トランジション、複数音声トラック、静止画修復などは維持している。

プライバシー：ユーザーの動画を公開GitHubへアップロードしない。ローカルのIndexedDBへ保存し、端末のブラウザにより削除される可能性はある。
