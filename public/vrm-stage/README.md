# Subeha.vrm 実モデル編集 — VRM STAGE v2

[Subeha.vrmを開く](https://nazonoryutarou-stack.github.io/subeha-portfolio/vrm-stage/?model=subeha)

## 既存VRMをそのまま使う

- リポジトリ直下の `Subeha.vrm`（19,553,252バイト）をGitHub Pagesデプロイ時に `models/Subeha.vrm` へ複製。リポジトリ内にバイナリを重複コミットしない。
- URLの `?model=subeha` からアクセスするとモデルの読み込みを開始。通常ページの「Subeha.vrmを読み込む」ボタンでも同様。
- オリジナルのVRMジオメトリ、テクスチャ、スキニング、元の表情を使用。簡略化した代替キャラクターに差し替えない。
- 20種類のヒューマノイド関節のX/Y/Z回転スライダー、7種のポーズプリセット、カット別ポーズ・動き・カメラ倍率を利用できる。
- VRM本体が持つ表情モーフ名を動的に一覧化し、音量連動口パク・まばたきを含めてカットごとの強さを設定できる。モデルに存在しない表情は操作可能なものとして扱わない。
- カメラをドラッグして向き変更、顔・上半身・全身への寄り、縦・横・正方形の画角、背景色の変更。
- モデル内の各材質の色味を調整できる。色は静止画・動画に反映し、設定JSONに保存。

## 書き出し

- **設定JSON**：カット割り、関節ポーズ、表情モーフ、カメラ、材質色など。VRMや音声の本体は含まれない。元ファイルを編集せず再利用できる。
- **PNG**：現在のプレビューフレームを保存。
- **動画**：ブラウザのMediaRecorderが対応する場合に実時間収録。音声を読んだ場合は音声付き、音声なしでも演技動画を収録できる。MP4が使えなければWebMとなり、Videoleapへの読み込み前に変換が必要な場合がある。
- **色変更版VRM**：GLBのJSONチャンクの glTF材質 `pbrMetallicRoughness.baseColorFactor` のみ変更し、元のバイナリチャンク、テクスチャ、ボーン、VRM拡張メタデータを保持する。GLTFLoaderの元材質インデックスとの対応が取れない場合はエラーにして保存しない。これは**材質の色だけ**を反映する方式で、ポーズ・カットアニメーションをVRMに焼き込むものではない。

## 制限と検証

- GitHubの内容とコード上での構造検証は実施済み。**実際の19.55MBモデルをAndroid端末で読み込んだ際のWebGL・音声付き動画収録・色変更VRMの実ファイル検証は未実施**。
- 端末のGPUやブラウザ、VRM固有のMToon材質との組み合わせで、一部機能が表示通りに働かない可能性がある。
- 関節の角度は最大±130度の編集値に限定。接地・IK・物理演算を自動補正する完全なポーズスタジオではない。
- VRMのボーン・表情はモデル内に存在するものだけ編集できる。
- 著作権・モデル利用条件は既存モデルのものを保持し、書き出したコピーでも元の権利を自動的には変更しない。

## 技術情報

- `shots.mjs`：関節回転、表情モーフ、カット、ポーズプリセットのデータモデル。
- `app.mjs`：実モデルロード、three-vrmボーン・表情制御、カメラ、WebAudio、動画収録、材質色編集。
- `recolor-vrm.mjs`：VRM元バイナリの保全を優先したGLB材質パッチ。
- `test/subeha-workbench.test.mjs`：ポーズ・カット・編集UIの基本テスト。

# VRM STAGE — 音声連動VRMカット演出

サイト: https://nazonoryutarou-stack.github.io/subeha-portfolio/vrm-stage/

**独立アプリの試作版**。VRM 0.x / VRM 1.0を自分の端末から読み込み、音声の再生時刻に応じて骨・表情・カメラを変化させます。映像編集の最終仕上げはVideoleap本家が担当します。

## できること
- VRM / GLB形式のうち、VRM拡張を持つ3Dモデルの読み込み（75MBまで）。
- 音声ファイルの読み込みと、音声の強弱による口パク。自動音素判定ではなくRMSベースの簡易同期です。
- 音声時刻でカット分割し、カットごとに表情6種・身振り7種・カメラ3距離・口の開き方・動きの強さ・左右の構図を指定。
- カット境界の位置調整、削除。モデルをドラッグしてカメラの角度を微調整。
- 9:16、16:9、1:1。PNG静止画。収録APIのあるブラウザでは音声付き動画の実時間キャプチャ。
- 設定JSONの保存・復元。JSONにはVRMや音声の本体を埋め込まないため、後日再び素材を読み込みます。

## 動画ファイルについて
`MediaRecorder.isTypeSupported()` によって、音声付きMP4が使えるブラウザではMP4、そうでない環境ではWebMを試します。特にAndroid ChromiumではWebMが選ばれることがあります。**WebMのままiPhone版Videoleapで読み込める保証はありません。** TermuxのFFmpegを使ってMP4に変換する場合（端末内で実施）:

```sh
pkg install ffmpeg
ffmpeg -i input.webm -c:v libx264 -pix_fmt yuv420p -c:a aac -movflags +faststart output.mp4
```

ファイル名・配置は各自の保存先に合わせて変更してください。書き出しは**音声の実時間の長さだけ**かかります。ブラウザのバックグラウンド停止・WebGLメモリ不足・MediaRecorder制約などで失敗する場合があります。

## 参照と権利
- [pixiv three-vrm](https://github.com/pixiv/three-vrm) — THREE.js + VRMLoaderPlugin、VRM表情・正規化ボーン。
- VRMモデル自体の商用利用・宗教・政治利用・モデル改変・クレジット表記はモデルごとに異なります。ロードできることと自由に使ってよいことは別です。
- 外部CDNからthree.js / three-vrmを読み込むため、初回表示にはインターネットが必要です。
- VRM・音声のファイルを当プロジェクトのサーバーへアップロードする処理はありません。
