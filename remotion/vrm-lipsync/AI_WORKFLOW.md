# AI切り抜き運用

**作業開始前に main の `docs/production-rules.md` を読むこと。**

## 原則

**面白さはAIが決める。時刻は音声から機械的に決める。**

AIは存在しない秒数を推測しない。字幕を勘で置かない。VRMを実際に検品せず完成扱いしない。

## 目標

音声と文字起こしをAIに渡したら、AIは主に**何を切り抜くか**を決める。
位置合わせはWhisper等の実タイムコードへ委ねる。

処理:

1. AIが文字起こしから「切るべき発言」を選ぶ
2. `jobs/current.json` に `quote` / `anchor` / タイトル / 前後余白を書く
3. `npm run clip`
4. タイムコードが無ければWhisper.cppが元音声を解析
5. `anchor` を認識結果から検索して区間を決定
6. 実音声を `atrim + asetpts` で正確に切る
7. 字幕を同じ0秒基準へ変換
8. 実音声から口パク波形を作る
9. 実VRMを直接レンダリング
10. QC画像を抽出し、冒頭・発話ピーク・中盤・オチを目視確認
11. QC合格後だけ完成品として返す

## AIが選ぶ基準

候補区間は原則15〜60秒。長くても90秒程度。

優先順位:

1. **一文で引っ掛かる** — 冒頭3秒以内に続きを聞きたくなる言葉がある
2. **本人にしか言えない** — 独自理論、変な比喩、強い断言、現場感
3. **単独で成立する** — 前後を知らなくても意味が通る
4. **展開がある** — 問い→説明→オチ等の小さい物語
5. **引用したくなる** — タイトルにできる一文がある
6. **既存切り抜きと被らない**

減点:

- 固有の相談者情報が必要
- 前置きだけで終わる
- 内輪文脈が強すぎる
- 長い沈黙・相槌が多い
- 医療・法律・危険行為等、短尺化で誤解が増える
- 切ると本人の意味が反転する

## AIが返すjob

推奨形:

```json
{
  "sourceAudio": "inputs/source.m4a",
  "sourceLabel": "Gravity 第158回",
  "quote": "AIで遊戯王のカードみたいにしたんですよ。破門になりました。",
  "anchor": "遊戯王のカードみたいにした",
  "contextBeforeMs": 12000,
  "contextAfterMs": 2500,
  "title": "遺影をAIでカード化したら破門された",
  "hook": "師匠は遺影を丁寧に残したかった。",
  "telop": ""
}
```

### quote

切り抜きの核。文字起こしを勝手に別の意味へ言い換えない。

### anchor

Whisper結果から検索する特徴句。6〜20文字程度を目安に、ASRでも崩れにくい箇所を使う。

### contextBeforeMs / contextAfterMs

前振りとオチに必要な分だけ残す。長くしすぎない。

### startMs / endMs

外部ASR等ですでに確定している時だけ使う。指定されていればquote検索より優先する。

## 字幕

- タイムコードはWhisper等の実測値を使う
- 明白なASR誤字は**文言だけ**補正する
- 例: 第158回「家」→「遺影」
- ASR由来の人工的な無音ギャップを補正する場合、理由を残す
- 要約文は逐語字幕と呼ばず「演出テロップ」とする

`quote` / `anchor` が見つからなければ、適当な時刻を推測せず停止する。

## VRM完成条件

以下を全部満たすまで完成扱いしない。

- Tポーズではない
- 腕・姿勢が自然
- 喋っている時に口が動く
- 実音声を使用
- 字幕が実発話に追従
- オチまで含まれる
- `out/qc/` の4枚を実際に確認済み

`npm run clip` 後に生成される:

```text
out/qc/start.png
out/qc/speech-peak.png
out/qc/middle.png
out/qc/end.png
```

フレーム抽出は自動だが、合否判定は目視。

## 禁止される近道

- 既成VRM MP4をループして「VRMが動いている」とする
- 口の動かない動画を口パク完成品として出す
- ASRを通さず秒数を推測する
- 要点カードを同期字幕として出す
- QCしていないレンダーを「できた」と返す

## 実行

```bash
cd remotion/vrm-lipsync
cp jobs/current.example.json jobs/current.json
# inputs/ に元音声を置き、jobを書き換える
npm run clip
```

出力: `out/kiritori.mp4`

## 理想のチャット運用

ユーザー:

> この音声と文字起こしから切り抜き作って

AI:

1. `docs/production-rules.md` を読む
2. 原本と公開可否を確認
3. 候補を比較し一本選ぶ
4. `quote` / `anchor` / タイトル / 余白を作る
5. `jobs/current.json` を作る
6. 実タイムコードでprepare
7. 実VRMでrender
8. QC画像を確認
9. 問題があれば修正して再render
10. 合格MP4のみ返す

ユーザーに同じ制作ルールを毎回説明させない。
